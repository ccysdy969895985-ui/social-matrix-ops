# ai-watchdog · 用 AI 监督 AI

盯着你在 WorkBuddy 里设的**自动运行任务**，一旦发现「该跑没跑 / 跑挂了 / 卡死了」，
立刻掀桌子告警，并把证据打包交给上层 AI 去判断和补跑。

## 它是怎么工作的

```
┌─────────────┐   只读扫描    ┌──────────────┐   诊断包    ┌──────────────┐
│ WorkBuddy   │ ───────────▶ │  watchdog.py │ ─────────▶ │  AI 监工      │
│ sqlite 运行库 │              │  检测引擎     │  latest.json│ 判断 + 补跑   │
└─────────────┘              └──────────────┘            └──────────────┘
                                     │
                                     └─▶ 响铃 + 语音 + 系统通知
```

* **检测引擎**（本脚本）：纯规则、零依赖、**只读数据库**，负责取证。
* **AI 监工**（WorkBuddy 定时自动化）：读懂诊断包，判断该不该补跑，并真的把任务拉起来。

## 判什么

| 类型 | 含义 | 严重级 |
|---|---|---|
| `STALLED` | 到点了却没触发（含调度器根本没排期的情况） | 高 |
| `OVERDUE_ONCE` | 一次性的任务错过了，没跑成 | 高 |
| `STUCK` | 单次运行迟迟不结束，疑似卡死 | 高 |
| `FAILED` | 确实报错了（6 小时内才算活问题） | 中 |
| `SILENT` | 超过正常周期仍未运行（兜底） | 低 |
| 💤 僵尸任务 | 列表里显示「启用」，但有效期已过，永远不会再跑 | 提示 |

### 两种「不算异常」的情况

| 分类 | 含义 | 处理 |
|---|---|---|
| `resolved` ✅ | 此前失败或逾期，但之后已有成功运行（含补跑任务）兜住 | 已平账，不报警、不补跑 |
| `historical` 📦 | 超出时间窗的隔夜旧账 | 只备查，不重复打扰 |

判断失败时**只认权威信号**：明确失败状态、`failure_code`、或 runtime 里的 `last_error`。
`PENDING_REVIEW`（跑完等人工确认，`result_success` 常为 0）**不再算失败** —— 这是早期版本
误报「明明发布了却说没完成」的根源。另外，「补跑｜原名｜10-08」会被归一回原任务同族，
族内只要有一次更晚的成功运行，相关旧账自动平账。

## 巡检节奏

监工**不按固定小时数轮询**，而是挂在各自动化任务的时点之后约 50 分钟触发，
一次只看「刚跑完的那批」。

下面是一份**示例巡检点**（来自原作者的实际档期，请按你自己的任务时间替换）：

| 巡检点 | 盯的任务 |
|---|---|
| 13:00 | AI 赚钱案例·第 1 场（12:10）→ 公众号 |
| 13:20 | 小红书赚钱案例·12:30 准时发 |
| 20:50 | 视频号自动发布（20:00） |
| 22:20 | 小红书赚钱案例定时推送（21:30） |
| 22:45 | AI 赚钱案例·第 2 场（21:55）→ 公众号 |

新增或调整自动化任务时，记得同步新增/调整对应的巡检点。

## 用法

```bash
WD=~/.workbuddy/ai-watchdog/watchdog.py

python3 $WD scan            # 体检报告（给人看）
python3 $WD scan --json     # 结构化诊断包（给 AI 看）
python3 $WD scan --alert    # 有异常时响铃 + 语音播报 + 系统通知
python3 $WD scan --wake     # 发现停摆时唤起 WorkBuddy，让调度器重新接手
python3 $WD brief           # 一行概览

python3 ~/.workbuddy/ai-watchdog/test_watchdog.py   # 判定逻辑回归测试（12 个场景）
```

退出码：`0` 一切正常 · `1` 发现异常 · `2` 运行出错 —— 方便被自动化或 cron 直接判断。

## 输出

* `state/latest.json` —— 最近一次体检的完整诊断包（AI 直接读这个）
* `reports/findings-*.json` —— 有异常时留档，默认保留 14 天

## 调参

在 `~/.workbuddy/ai-watchdog/config.json` 里覆盖（不存在则用默认值）：

```json
{
  "grace_minutes": 45,        // 到点后多久没触发算停摆（调度器常晚 7~50 分钟，别调太小）
  "stuck_minutes": 90,        // 跑多久没结束算卡死
  "silent_factor": 1.8,       // 静默判定：周期 × 该倍数
  "failed_fresh_hours": 6,    // 多久内的失败才算「活问题」，更早的降级为旧账
  "stale_days": 3,            // 停摆多少天提示「疑似废弃」
  "report_retention_days": 14
}
```

## 安全边界

* 数据库以 `mode=ro` 只读打开，**不会**修改、停用或删除任何自动化任务。
* `--wake` 仅调用 `open -a WorkBuddy`（已运行则只是切到前台），不写任何数据。
* 真正的「补跑」动作由上层 AI 通过正规接口创建**新的**一次性任务完成，原任务不受影响。
